# 两阶段 AE-SVDD 联邦恶意参与方检测：论文版实验方案

**版本**：2026-07-31  
**代码入口**：`src/run_sweep.py`、`src/run_matrix.py`  
**实验依据**：`experiment.docx`（用户提供版本）、现有 `article/experiment.md`、代码实现及 FLDetector、FedDMC、FLAD、FLAME、FoolsGold 等论文。

> 说明：`experiment.docx` 的原始默认值是 Dir(β=0.5)、50 个客户端、15 个恶意客户端。根据本文的多数良性参与方假设和当前代码能力，主实验将其调整为 **K=50/100/200、恶意比例 10%--40%、IID 与轻度 Dir(α=1.0)**；β=0.5 等更强异质性只作为环境压力实验。当前代码中的 MNIST/Fashion-MNIST 使用灰度 ResNet-18，CIFAR-10 使用 ResNet-18，AG News 使用 Transformer 分类器，因此不照搬 docx 中“CNN/TextCNN”的架构表述。

## 摘要

本文研究一种不依赖服务器根数据集的两阶段 AE-SVDD 防御。第一阶段以客户端模型特征的自编码器重建误差进行鲁棒筛选，第二阶段在可信表示上学习单类中心并进行硬隔离与聚合。实验需要同时回答三个问题：方法能否保持干净任务精度，能否识别模型/梯度投毒与后门上传，以及两个阶段是否具有互补作用。为避免把 non-IID 误写成方法贡献，IID 和 α=1.0 作为主结果环境，α=0.5、0.1 仅用于压力测试。所有结论使用至少 3 个随机种子，并报告均值、标准差和原始 JSON。

## 1. 研究问题与假设

**RQ1（总体效用）**：在多种攻击和四个数据集上，AE-SVDD 的 Clean Accuracy/TACC、后门 ASR 和检测指标是否优于无防御及已复现的鲁棒聚合方法？

**RQ2（检测能力）**：在恶意比例 10%--40%、客户端数 50--200 时，方法能否保持较高 RR/TPR、DPR/Precision、DAR 和较低良性 FPR？

**RQ3（阶段归因）**：Phase 1 是否更容易发现高范数、方向反转或高斯噪声等模型/梯度攻击；Phase 2 是否能在参数统计相近时持续降低数据投毒/后门影响？这是可证伪假设，不是预设结论。

**RQ4（环境边界）**：当 α 从 1.0 降到 0.5、0.1 时，正常客户端漂移是否造成误筛和性能下降？

**RQ5（成本与可扩展性）**：特征压缩维度和客户端规模如何影响每轮检测耗时、显存和通信量？

## 2. 威胁模型与方法边界

每轮服务器可见单个客户端上传的模型状态或更新，但不访问训练数据、干净验证集或后门触发样本。恶意客户端位于最后 `K-num_benign` 个 ID，攻击者知道训练协议并可协同。主实验始终满足良性客户端占多数；50% 及以上只作为边界，不纳入主结论。

本文将攻击按观测信号分为：

1. **模型/梯度级**：Gaussian（`gn`）、Sign Flip（`sf`）、Scaling/Model Replacement、LIE/ALIE（`lie`）。
2. **数据/目标级**：Label Flipping（`lf`）、Backdoor（`bd`）。图像后门使用固定方形触发器，AG News 使用目标词/目标标签投毒；文本后门的 ASR 单独定义，不能与图像 ASR 混写。
3. **混合攻击**：同一轮由不同恶意客户端同时执行多种攻击，而不是每轮只选择一种攻击。默认 `M1=LF+Backdoor+Gaussian`；扩展 `M2=LF+Sign Flip+LIE`、`M3=LF+Backdoor+Gaussian+LIE`。代码按恶意客户端 ID 确定性轮换分配，JSON 保存 `mixed_attack_types`，便于按攻击族归因。

Phase 1 的合理假设是“模型/梯度攻击在所选特征上有较高重建误差”；Phase 2 的合理假设是“部分数据投毒上传仍偏离可信潜在区域”。无根数据条件下，隐蔽后门可能与良性上传不可分，因此论文必须报告失败案例，不能写成两个阶段具有必然攻击覆盖能力。

## 3. 数据集、模型与数据划分

主表使用四个数据集，回答跨视觉和语言任务的泛化问题：

| 数据集 | 模态/类别 | 当前代码模型 | 主要用途 |
|---|---|---|---|
| MNIST | 灰度图像/10 类 | 灰度 ResNet-18 | 基础检测和快速复现 |
| Fashion-MNIST | 灰度图像/10 类 | 灰度 ResNet-18 | 更难的灰度视觉任务 |
| CIFAR-10 | RGB 图像/10 类 | CIFAR ResNet-18 | 主复杂视觉任务 |
| AG News | 文本/4 类 | Transformer 文本分类器 | 跨模态泛化；文本后门单独报告 |

主环境包含两档：`IID` 与 Dir(α=1.0)。α=1.0 是轻度 non-IID，只作为现实环境因素，不声称方法解决 client drift。α=0.5 和 0.1 放入 E-NIID 压力实验；可在附录保留 α=5.0 作为近似 IID 对照，但不替换 IID 主设置。每个 task/K/α/seed 的数据划分由 `run_sweep.py` 缓存，攻击和防御共享完全相同的划分。

## 4. 防御对比

主表只使用当前代码中真实注册、可运行且参数接口一致的方法：

| ID | 方法 | 角色 |
|---|---|---|
| `avg` | FedAvg | 无防御上界/误伤检查 |
| `tm` | Trimmed Mean | 坐标统计基线 |
| `mk` | Multi-Krum | 距离几何基线 |
| `lasa` | LASA | 层自适应稀疏聚合扩展基线 |
| `seca` | FedSECA | 代码已复现的无根数据方法 |
| `fld` | FL-Defender | 代码中的 `fld` 明确指 FL-Defender，不写成 FLDetector |
| `dmc` | FedDMC-style multi-view detector | 更新范数、方向、符号、稀疏度和跨轮 EMA |
| `svdd` | 本文两阶段 AE-SVDD | 主方法 |

FLDetector、BRAFL、FLARE、GShield、FLAME、DeepSight、FLAD 等论文方法只有在完成统一代码复现后才能加入数值主表；当前未接入的方法在论文中列为相关工作/待复现，不冒充已完成基线。所有方法使用相同模型、数据划分、客户端 ID、轮数和随机种子。

## 5. 统一训练协议

默认论文运行：总轮数 300，本地 epoch 1，batch size 64，客户端学习率、优化器和 AE 超参数沿用 `FedConfig` 默认值；正式结果使用种子 42、43、44（资源允许时增加 45、46）。K 取 50、100、200，恶意比例取 10%、20%、30%、40%，并四舍五入得到恶意客户端数，至少保留 1 个良性客户端。

每个配置必须记录：Git commit、数据集/模型、K、恶意数、攻击及混合攻击映射、α、seed、设备、总轮数、检测耗时、峰值显存和 JSON 路径。`none` 攻击用于验证无攻击时的良性 FPR，不能只跑有攻击设置。

## 6. 主实验（E1）

主实验是四数据集 × 攻击 × 防御的完整矩阵，默认 K=100、恶意比例 30%、IID 与 α=1.0 各一组；K=50/200 和 10%/20%/40% 在同一矩阵中作为规模/比例扩展。攻击至少包含 `lf,gn,sf,lie,bd,mix`，其中 `mix` 默认 `lf,bd,gn`，并单独报告 M2/M3。

建议命令（先用 3 seeds 验证，再扩大矩阵）：

```bash
dl/bin/python -m src.run_sweep \
  --tasks mnist,fashion_mnist,cifar10,ag_news \
  --attacks none,lf,gn,sf,lie,bd,mix \
  --mixed-attack-types lf,bd,gn \
  --defenses avg,tm,mk,dmc,svdd \
  --clients 50,100,200 --rates 0.1,0.2,0.3,0.4 \
  --alphas iid,1.0 --seeds 42,43,44 --rounds 300 \
  --device cuda --output-dir log/E1_main
```

主表按数据集分块，单元格报告 `TACC / DAR / DPR / RR / FPR / AUROC`；后门行另外报告 `ASR`。四个数据集应放在同一张总表或四个子表中，而不是只跑 CIFAR-10。不同任务的绝对准确率不直接横向排名，只比较相对防御收益和检测质量。

## 7. 阶段归因实验（E2）

为验证“两阶段分别处理两类攻击”的解释，固定 CIFAR-10、K=100、30% 恶意、IID/α=1.0，各运行 `gn,sf,lie,lf,bd,mix`：

| 版本 | 配置 | 解释 |
|---|---|---|
| P1-only | `phase1_rounds=300`，关闭 Phase 2 | 观察重建误差对模型/梯度攻击的识别 |
| P2-only | `phase1_rounds=0` | 观察无预热时潜在中心和聚合效果 |
| Full | `phase1_rounds=15`，`phase1_selection=reconstruction` | 本文主方法 |
| Legacy | `phase1_selection=feature_median` | 区分旧中位数规则与重建误差 |

按阶段报告新增 TPR/FPR、累计 TPR/FPR、保留率、TACC 和后门 ASR；不能用最终准确率反推某阶段有效。若 P2-only 在后门上有效但检测分数不分离，应表述为聚合抑制而非“准确识别”。

## 8. 混合攻击实验（E3）

混合攻击是主实验因素，不放到附录。每轮保持恶意客户端分组不变，记录每个恶意 ID 的攻击类型。比较：

* `M1`：LF + Backdoor + Gaussian，覆盖数据、目标和明显模型投毒；
* `M2`：LF + Sign Flip + LIE，覆盖反向、标签和统计伪装；
* `M3`：LF + Backdoor + Gaussian + LIE，作为最完整组合。

结果除总体指标外，按攻击类型计算恶意客户端 RR/FPR，并绘制每类攻击的重建误差和 Phase-2 距离箱线图。混合后门运行会在 JSON 的每轮 `backdoor_asr` 中记录独立触发测试结果。

## 9. 环境、比例与规模实验

**E-NIID（环境因素）**：固定 K=100、30% 恶意，运行 IID、α=1.0、0.5、0.1；同时运行 `none` 和 `lf`。报告正常客户端类别熵/样本量、FPR、TACC 和 RR。结论只描述性能退化与适用边界，不称 non-IID 为方法机制。

**E-rate（恶意比例）**：固定 K=100、CIFAR-10、α=1.0，比例 10%、20%、30%、40%；50% 单独作为多数正常假设失效的边界图，不进入主表均值。

**E-scale（客户端规模）**：固定 30% 恶意、α=1.0，K=50、100、200，记录 TACC、RR/FPR、每轮耗时、峰值显存和日志大小。若 200 客户端超出显存，采用串行客户端模型复用并保留相同数据划分。

## 10. 消融与针对性实验

必须完成的消融包括：

1. `svdd_input_mode=absolute/delta`：绝对模型状态与模型增量；
2. `svdd_feature_mode=task/fixed_projection`，压缩维度 `k∈{10,50,100,500,1000}`：验证高维压缩与检测耗时；
3. 动态阈值退火 vs 静态阈值；
4. AE 重建项 vs 潜在紧致项；
5. 历史 EMA、符号、方向、稀疏度视角逐一关闭（`dmc` 消融）；
6. 攻击强度曲线：Gaussian σ、Sign Flip scale、后门 poison ratio/model-replacement scale、LIE z；
7. 时间模式：前期、后期、间歇和轮换攻击，报告首次检测轮次；
8. 协同/Sybil 更新和自适应“最小化重建误差”攻击，验证方法上限；
9. 无攻击客户端累计误筛审计，按样本量和类别熵分层；
10. 恢复策略：继续聚合、最近可信模型回滚、可信集合重聚合。

其中 1、2、6、7、8 直接检验 AE-SVDD 的方法特色；不能只增加更多数据集而不做这些针对性实验。

## 11. 评价指标与统计分析

* **效用**：Clean Accuracy/TACC、测试损失、Accuracy Drop、达到目标精度的轮数。
* **后门**：Clean Accuracy 和 ASR；ASR 仅对有明确触发测试集的攻击报告。
* **检测**：DAR、DPR/Precision、RR/Recall、F1、TPR、良性 FPR、每轮保留率。
* **连续分数**：由 `detection_scores` 计算 AUROC/AUPRC；只有单一类别时记为 `NA`。
* **成本**：总墙钟时间、每轮检测/聚合时间、峰值 GPU 显存、特征维度、输出大小。

每个配置至少 3 个 seeds，报告均值 ± 标准差；主表采用最后 10 轮均值，另报最后一轮和最好精度。跨方法比较使用配对 bootstrap 或 Wilcoxon signed-rank，并注明客户端-轮次指标采用 macro 还是 micro 口径。

## 13. 与相关论文实验的关系

FLDetector（KDD 2022）和 FedDMC（TDSC 2024）都使用多数据集、多攻击、恶意比例和检测延迟/历史消融；FLAD（TDSC 2025）进一步覆盖模型投毒、后门、adaptive attack 和效率；FLAME、DeepSight 重点报告后门 ASR 与干净精度；FoolsGold 重点是协同/Sybil 攻击。领域论文通常不是只跑一个数据集，但也有工作只针对后门或单一任务，因此本文选择“四数据集主表 + 混合攻击 + 阶段归因”比只复制单一数据集更能支撑方法特色。FedGT 等安全聚合工作属于服务器看不到单客户端更新的不同威胁模型，不与本文主表直接混合。

## 14. 限制与可复现性

AE-SVDD 依赖服务器观察单客户端更新；在完全安全聚合下不能直接提取当前特征。单中心假设依赖多数良性客户端，α 很小或恶意比例接近 50% 时可能发生中心污染。后门若在上传统计上伪装成良性，当前无根数据检测器可能只能降低 ASR 而不能准确标记客户端。论文只报告实际完成的实验，不把预期 TPR/ASR 写成结果。

每一阶段执行前后创建 Git 提交并记录：commit、命令、设备、依赖版本、数据缓存位置和输出目录。推荐顺序为 E0 冒烟、E1 主表、E2 阶段归因、E3 混合攻击、E-NIID/E-rate/E-scale、消融和自适应攻击；任一阶段失败时保留日志并修复后重新提交，不覆盖旧结果。
