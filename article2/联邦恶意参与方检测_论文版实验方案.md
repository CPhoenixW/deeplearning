# 两阶段 AE-SVDD 联邦恶意参与方检测：论文版实验方案

**版本**：2026-07-31  
**代码入口**：模块化流水线 `src/pipeline.py`（配置在 `configs/`）；批量参数扫描兼容入口为 `src/run_sweep.py`、`src/run_matrix.py`。
**实验依据**：`experiment.docx`（用户提供版本）、现有 `article/experiment.md`、代码实现及 FLDetector、FedDMC、FLAD、FLAME、FoolsGold 等论文。

> 说明：`experiment.docx` 的原始默认值是 Dir(β=0.5)、50 个客户端、15 个恶意客户端。根据本文的多数良性参与方假设和当前代码能力，主实验将其调整为 **K=50/100/200、恶意比例 10%--40%、IID 与轻度 Dir(α=1.0)**；β=0.5 等更强异质性只作为环境压力实验。当前代码中的 MNIST/Fashion-MNIST 使用灰度 ResNet-18，CIFAR-10 使用 ResNet-18，AG News 使用 Transformer 分类器，因此不照搬 docx 中“CNN/TextCNN”的架构表述。

## 摘要

本文研究一种不依赖服务器根数据集的两阶段 AE-SVDD 防御。第一阶段以客户端模型特征的自编码器重建误差进行鲁棒筛选，第二阶段在可信表示上学习单类中心并进行硬隔离与聚合。全文实验严格围绕五个研究问题展开：总体效用、攻击覆盖、两阶段互补性、环境边界、计算与可扩展性。为避免把 non-IID 误写成方法贡献，IID 和 α=1.0 作为主结果环境，α=0.5、0.1 仅用于压力测试。所有结论使用至少 3 个随机种子，并报告均值、标准差和原始 JSON。

## 1. 研究问题与假设

**RQ1（总体效用）**：在多种攻击和四个数据集上，AE-SVDD 的 Clean Accuracy/TACC、后门 ASR 和检测指标是否优于无防御及已复现的鲁棒聚合方法？对应主实验 E1。

**RQ2（攻击覆盖）**：面对模型/梯度攻击、数据/后门攻击以及多种攻击并发的混合攻击，方法能否保持较高 RR/TPR、DPR/Precision、DAR 和较低良性 FPR？对应攻击覆盖与混合攻击实验 E2。

**RQ3（阶段互补）**：Phase 1 是否更容易发现高范数、方向反转或高斯噪声等模型/梯度攻击；Phase 2 是否能在参数统计相近时持续降低数据投毒/后门影响；两阶段联合是否优于任一单阶段？对应阶段组合实验 E3。这是可证伪假设，不是预设结论。

**RQ4（环境边界）**：在数据异质性、恶意比例、客户端规模、攻击强度和任务/模型变化时，方法的误筛、漏检和任务效用如何变化？对应环境边界实验 E4。

**RQ5（成本与可扩展性）**：特征压缩维度、客户端规模和执行方式如何影响每轮检测耗时、显存、通信量和结果稳定性？对应成本与扩展实验 E5。

## 2. 威胁模型与方法边界

每轮服务器可见单个客户端上传的模型状态或更新，但不访问训练数据、干净验证集或后门触发样本。恶意客户端位于最后 `K-num_benign` 个 ID，攻击者知道训练协议并可协同。主实验始终满足良性客户端占多数；50% 及以上只作为边界，不纳入主结论。

本文将攻击按观测信号分为：

1. **模型/梯度级**：Gaussian（`gn`）、Sign Flip（`sf`）、Scaling/Model Replacement、LIE/ALIE（`lie`）。
2. **数据/目标级**：Label Flipping（`lf`）、Backdoor（`bd`）。图像后门使用固定方形触发器，AG News 使用目标词/目标标签投毒；文本后门的 ASR 单独定义，不能与图像 ASR 混写。
3. **混合攻击**：同一轮由不同恶意客户端同时执行多种攻击，而不是每轮只选择一种攻击。默认 `M1=LF+Backdoor+Gaussian`；扩展 `M2=LF+Sign Flip+LIE`、`M3=LF+Backdoor+Gaussian+LIE`。代码按恶意客户端 ID 确定性轮换分配，JSON 保存 `mixed_attack_types`，便于按攻击族归因。

Phase 1 的合理假设是“模型/梯度攻击在所选特征上有较高重建误差”；Phase 2 的合理假设是“部分数据投毒上传仍偏离可信潜在区域”。无根数据条件下，隐蔽后门可能与良性上传不可分，因此论文必须报告失败案例，不能写成两个阶段具有必然攻击覆盖能力。

## 3. 数据集、模型与数据划分

主表使用四个数据集，回答跨视觉和语言任务的泛化问题：

| 数据集 | 模态/类别 | 当前代码模型 | 主要用途 |
|---|---|---|---|
| MNIST | 灰度图像/10 类 | 灰度 ResNet-18 | 基础检测和快速复现 |
| Fashion-MNIST | 灰度图像/10 类 | 灰度 ResNet-18 | 更难的灰度视觉任务 |
| CIFAR-10 | RGB 图像/10 类 | CIFAR ResNet-18 | 主复杂视觉任务 |
| AG News | 文本/4 类 | Transformer 文本分类器 | 跨模态泛化；文本后门单独报告 |

主环境包含两档：`IID` 与 Dir(α=1.0)。α=1.0 是轻度 non-IID，只作为现实环境因素，不声称方法解决 client drift。α=0.5 和 0.1 放入 E4 环境边界实验；可在附录保留 α=5.0 作为近似 IID 对照，但不替换 IID 主设置。每个 task/K/α/seed 的数据划分由 `run_sweep.py` 缓存，攻击和防御共享完全相同的划分。

## 4. 防御对比

主表只使用当前代码中真实注册、可运行且参数接口一致的方法：

| ID | 方法 | 角色 |
|---|---|---|
| `avg` | FedAvg | 无防御上界/误伤检查 |
| `tm` | Trimmed Mean | 坐标统计基线 |
| `mk` | Multi-Krum | 距离几何基线 |
| `lasa` | LASA | 层自适应稀疏聚合扩展基线 |
| `seca` | FedSECA | 代码已复现的无根数据方法 |
| `fld` | FL-Defender | 代码中的 `fld` 明确指 FL-Defender，不写成 FLDetector |
| `dmc` | FedDMC-style multi-view detector | 更新范数、方向、符号、稀疏度和跨轮 EMA |
| `svdd` | 本文两阶段 AE-SVDD | 主方法 |

FLDetector、BRAFL、FLARE、GShield、FLAME、DeepSight、FLAD 等论文方法只有在完成统一代码复现后才能加入数值主表；当前未接入的方法在论文中列为相关工作/待复现，不冒充已完成基线。所有方法使用相同模型、数据划分、客户端 ID、轮数和随机种子。

## 5. 统一训练协议

默认实验设置：总轮数 300，本地 epoch 1，batch size 64，客户端学习率、优化器和 AE 超参数沿用 `FedConfig` 默认值；正式结果使用种子 42、43、44（资源允许时增加 45、46）。K 取 50、100、200，恶意比例取 10%、20%、30%、40%，并四舍五入得到恶意客户端数，至少保留 1 个良性客户端。

每个配置必须记录：Git commit、数据集/模型、K、恶意数、攻击及混合攻击映射、α、seed、设备、总轮数、检测耗时、峰值显存和 JSON 路径。`none` 攻击用于验证无攻击时的良性 FPR，不能只跑有攻击设置。

## 6. 评价指标与统计分析

* **效用**：Clean Accuracy/TACC、测试损失、Accuracy Drop、达到目标精度的轮数。
* **后门**：Clean Accuracy 和 ASR；ASR 仅对有明确触发测试集的攻击报告。
* **检测**：DAR、DPR/Precision、RR/Recall、F1、TPR、良性 FPR、每轮保留率。
* **连续分数**：由 `detection_scores` 计算 AUROC/AUPRC；只有单一类别时记为 `NA`。
* **成本**：总墙钟时间、每轮检测/聚合时间、峰值 GPU 显存、特征维度、输出大小。

每个配置至少 3 个 seed，报告均值 ± 标准差；主表采用最后 10 轮均值，另报最后一轮和最好精度。跨方法比较使用配对 bootstrap 或 Wilcoxon signed-rank，并注明客户端-轮次指标采用 macro 还是 micro 口径。

## 7. RQ1：总体效用主实验（E1）

主实验是四数据集 × 攻击 × 防御的完整矩阵，默认 K=100、恶意比例 30%、IID 与 α=1.0 各一组；K=50/200 和 10%/20%/40% 在同一矩阵中作为规模/比例扩展。攻击至少包含 `lf,gn,sf,lie,bd,mix`，其中 `mix` 默认 `lf,bd,gn`，并单独报告 M2/M3。

主表按数据集分块，单元格报告 `TACC / DAR / DPR / RR / FPR / AUROC`；后门行另外报告 `ASR`。四个数据集应放在同一张总表或四个子表中，而不是只跑 CIFAR-10。不同任务的绝对准确率不直接横向排名，只比较相对防御收益和检测质量。

## 8. RQ2：攻击覆盖与混合攻击实验（E2）

主实验攻击按三组报告：模型/梯度级（`gn,sf,lie`）、数据/目标级（`lf,bd`）和混合攻击（`M1,M2,M3`）。混合攻击不是把攻击类型按轮次随机替换，而是同一轮由不同恶意客户端并发执行不同攻击；每个恶意 ID 的类型必须写入 JSON。

* `M1`：LF + Backdoor + Gaussian；
* `M2`：LF + Sign Flip + LIE；
* `M3`：LF + Backdoor + Gaussian + LIE。

固定 CIFAR-10、K=100、30% 恶意、IID 和 α=1.0，各攻击运行 `avg,tm,mk,dmc,svdd`。除总体 TACC、DAR、DPR、RR、FPR、AUROC 外，按攻击族报告恶意客户端 RR/FPR；混合后门另外报告每轮 ASR。四数据集主表至少包含单一攻击和 M1，M2/M3 作为混合攻击扩展表。

## 9. RQ3：Phase 1/Phase 2 互补性实验（E3）

为验证“两阶段分别处理两类攻击”的解释，固定 CIFAR-10、K=100、30% 恶意、IID/α=1.0，各运行 `gn,sf,lie,lf,bd,M1`。E3 必须同时包含单阶段和联合阶段，不能只比较 P1-only 与 P2-only：

| 版本 | 配置 | 解释 |
|---|---|---|
| 无检测控制 | `defense=avg` | 确认指标不是由检测模块以外因素造成 |
| P1-only | `phase1_rounds=total_rounds`，不进入 Phase 2 | 观察重建误差对模型/梯度攻击的识别 |
| P2-only | `phase1_rounds=0`，第一轮直接启用 Phase 2 | 观察无预热时潜在中心和聚合效果 |
| P1+P2（Full） | `phase1_rounds=15`，`phase1_selection=reconstruction` | 本文完整的顺序组合，P1 输出可信集合并初始化 P2 |

按阶段报告新增 TPR/FPR、累计 TPR/FPR、保留率、TACC 和后门 ASR；联合版本还要报告 P1 结束时的保留集合、P2 首次检测轮次以及两阶段累计误筛率。若 P2-only 在后门上有效但检测分数不分离，应表述为聚合抑制而非“准确识别”。

## 10. RQ4：环境边界实验（E4）

环境边界不只改变 alpha，而是分解为以下相互独立的因素。主结论仍固定 IID/α=1.0 和良性多数，边界结果单独报告：

1. **数据异质性**：IID、α=1.0、0.5、0.1；报告类别熵、样本量、FPR、RR 和 TACC。
2. **恶意比例**：10%、20%、30%、40%；50% 只作为多数良性假设失效的边界点。
3. **客户端规模**：K=50、100、200；固定恶意比例时同步增加恶意数，而不是固定恶意客户端数量。
4. **攻击强度**：Gaussian σ、Sign Flip scale、LIE z、后门 poison ratio 和 model-replacement scale 分级扫描，绘制“攻击效果--检测率”曲线。
5. **任务/模型边界**：MNIST、Fashion-MNIST、CIFAR-10、AG News；不比较绝对准确率，只比较相对防御收益、检测质量和成本。

当前扫描器已覆盖 K、恶意比例、alpha、攻击强度参数和四个任务；E4 不包含需要额外改代码的样本量不均衡、部分参与或攻击时序实验。

## 11. RQ5：成本、压缩与可扩展性实验（E5）

固定 CIFAR-10、30% 恶意、α=1.0，在 K=50/100/200 下比较 `tm,mk,dmc,svdd`。分别扫描固定投影维度 `k∈{64,256,1024,4096,8192}`、串行与 CUDA batched client executor，报告 TACC、RR/FPR、每轮训练时间、检测时间、峰值显存、通信量、日志大小和结果方差。
