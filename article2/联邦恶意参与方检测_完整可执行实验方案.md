# 联邦学习恶意参与方检测：完整可执行实验方案

**版本**：2026-07-31  
**方法**：两阶段 AE-SVDD（模型特征 + Median--MAD + 潜在空间单类距离 + 硬筛选）  
**代码入口**：[`src/run_sweep.py`](src/run_sweep.py)、[`src/run_matrix.py`](src/run_matrix.py)

## 1. 研究目标和可检验假设

本实验不只比较最终准确率，同时验证“检测是否有效”和“是否误伤正常 non-IID 客户端”。服务器不读取根数据集；实验中的恶意客户端身份只用于离线评测，不参与防御决策。

- **RQ1 效用**：攻击下 AE-SVDD 是否比 FedAvg、Trimmed Mean、Multi-Krum 保持更高的干净测试准确率？
- **RQ2 检测**：是否能提高恶意客户端 TPR/Precision/F1，并控制良性客户端 FPR？
- **RQ3 非 IID**：Dirichlet α 变小时，方法的误筛率如何变化？两阶段预热是否比首轮筛选更稳？
- **RQ4 机制**：重建预热、固定中心、紧致度损失、阈值退火和特征输入形式是否各自必要？
- **RQ5 代价**：每轮检测时间、总训练时间、峰值显存和日志大小是否可接受？

论文中只报告实际运行结果，不把“预期 TPR > 90%”当成结论。每个主结果至少使用 3 个随机种子，报告均值 ± 标准差，并保留完整 JSON 以便审计。

## 2. 方法和实现边界

### 2.1 方法流程

1. 客户端按 IID 或 Dirichlet(α) 划分数据，本地训练并上传模型状态；
2. 服务端提取 BN/LN 特征（可选固定层次多视图投影），用当轮 Median--MAD 做鲁棒缩放；
3. **Phase 1** 只训练 AE 重建表示并进行包容性聚合，不使用 SVDD 中心距离做最终检测；
4. 预热结束后由低重建误差表示初始化中心 (c)，**Phase 2** 固定/EMA 更新中心，联合重建损失和潜在紧致度损失；
5. 计算 (d_k=\|z_k-c\|_2^2)，阈值为 `median(d)+tau*MAD(d)`，`tau_start -> tau_end` 退火；
6. 可信客户端按掩码参与聚合，并将每轮检测分数、掩码、TPR/FPR、准确率写入 JSON。

### 2.2 当前代码支持的攻击和防御

| 类别 | 代码 ID | 实现方式 |
|---|---|---|
| 无攻击 | `none` | 所有客户端使用良性本地训练；用于 clean 保真性 |
| 标签翻转 | `lf` | (y'=(C-1)-y) |
| 高斯模型投毒 | `gn` | 按全局每层均值/方差生成噪声模型 |
| 符号翻转 | `sf` | (g-\gamma(local-g)) |
| LIE/ALIE | `lie` | 服务器用良性更新统计量构造 μ+zσ |
| 后门/模型替换 | `bd` | 方形触发器、目标标签、模型替换倍率 |

已实现防御：`avg`、`tm`、`mk`、`svdd`、`lasa`、`seca`、`fld`、`alignins`、`bnguard`、`flgmm`、`flanders`。FoolsGold、FLAME、DeepSight、FLAD 等论文方法作为相关工作和后续扩展，不在当前可执行主矩阵中冒充已复现基线；需要新增实现后再纳入公平比较。

## 3. 实验因素和统一协议

### 3.1 主实验默认设置

| 因素 | 默认值 | 扩展值 |
|---|---:|---:|
| 数据集/模型 | CIFAR-10 / ResNet-18 | Fashion-MNIST / ResNet-18；AG News / Transformer |
| 客户端数 K | 10 | 20、50、100 |
| 恶意比例 | 30% | 10%、20%、40%（50% 仅作边界实验） |
| 数据分布 | IID | Dirichlet α=1.0、0.5、0.1 |
| 总轮数 | 50（冒烟）/ 300（论文） | 10、100、300 |
| 本地 epoch | 1 | 2（敏感性） |
| batch size | 64 | 32（CIFAR 资源足够时） |
| 随机种子 | 42、43、44 | 45、46（最终表格） |
| 设备 | `cuda` | `cpu` 仅用于功能测试 |

除正在研究的因素外，所有比较必须复用同一 `seed`、同一客户端数据划分、同一恶意客户端 ID（默认最后 `K-num_benign` 个）和同一训练轮数。`run_sweep.py` 已按 task/K/α/seed 缓存 dataloader，保证攻击和防御之间是配对比较。

### 3.2 对比方法

1. `avg`：无防御上界；
2. `tm`：坐标 Trimmed Mean，`trimmed_mean_num_byzantine` 与真实恶意数一致；
3. `mk`：Multi-Krum，`krum_num_byzantine` 与真实恶意数一致；
4. `svdd`：本文完整两阶段 AE-SVDD；
5. `lasa`、`seca`、`fld`：代码中已移植的代表性无根数据方法，用作扩展表；
6. `bnguard`、`flgmm`、`flanders`、`alignins`：检测机制拆解/扩展比较，不与主表混淆。

### 3.3 评价指标

- **模型效用**：Clean Accuracy、测试损失（若记录）、Accuracy Drop、达到目标准确率所需轮数；
- **后门**：Clean Accuracy 与 ASR。当前代码的 `bd` 已提供触发器训练；应另外构造带触发器的测试集计算 ASR，不能把 Clean Accuracy 当 ASR；
- **检测**：TPR/Recall、FPR、Precision（JSON 的 `dpr`）、F1、整体 DAR、每轮保留率；
- **连续分数**：每轮 JSON 的 `detection_scores` 可计算 AUROC/AUPRC。分数恒定或只有一个类别时记为 `NA`；
- **代价**：总墙钟时间、单轮平均时间、峰值 GPU 显存、参数/特征维度、输出文件大小；
- **稳定性**：均值、标准差、95% bootstrap 置信区间；不要只报告单个最好 seed。

固定 K=10、恶意率 30%、α=0.5，运行 `lf/gn/sf/lie/bd`。`bd` 同时记录 Clean Accuracy 和独立触发测试集 ASR；`lie` 必须保证良性客户端数大于 1，并在报告中说明 `lie_z_override` 或自动 z 的取值。

```bash
dl/bin/python -m src.run_sweep --tasks cifar10 \

应特别分析：强可见攻击（`gn/sf`）与统计伪装攻击（`lie`）的差异；`bd` 的模型替换倍率和 poison ratio 不能在不同防御间改变。

### E5：两阶段和损失函数消融

固定 E1 的数据、攻击客户端和 seeds，每次只改一个参数：

| 变体 | 配置改动 | 目的 |
|---|---|---|
| 完整方法 | `phase1_rounds=15`，`svdd_recon_lambda=0.1` | 主方法 |
| 无预热 | `phase1_rounds=0` | 验证早期筛选误伤 |
| 仅重建 | `svdd_recon_lambda=0` 且不启用紧致度（需实现开关） | 验证 SVDD 项 |
| 仅紧致 | 第二阶段去掉重建项（需实现开关） | 验证防坍塌作用 |
| 无固定中心 | 中心每轮完全重算（需实现开关） | 验证中心漂移风险 |
| 无退火 | `tau_start=tau_end` | 验证阈值收紧 |
| 输入消融 | `svdd_input_mode=absolute/delta` | 验证模型绝对量与更新量 |
| 特征消融 | `svdd_feature_mode=task/fixed_projection`，维度 4096/8192 | 验证压缩和计算代价 |

当前代码已支持 `svdd_input_mode` 和固定投影特征；损失/中心开关应在提交消融结果前实现为显式配置，不能手改服务器代码后混入主实验。

  --alphas 0.5 --seeds 42,43,44 --rounds 100 --device cuda --output-dir log/E6_tasks
```

## 5. 结果汇总和统计规则

每个 JSON 的 `summary.mean_last_10` 作为主表候选；同时保留 `last` 和 `best_test_acc`，禁止以 best 代替最终性能。推荐输出以下表格：

1. **主表**：攻击 × 防御的 Clean Accuracy、TPR、FPR、F1、AUROC；
2. **后门表**：Clean Accuracy、ASR、恶意客户端保留率；
3. **non-IID 图**：α × FPR/TPR/Accuracy；
4. **比例图**：恶意率 × TPR/FPR/Accuracy；
5. **机制图**：完整方法与消融的训练曲线、潜在空间方差、每轮保留率；
6. **代价表**：K × 单轮耗时、总耗时、峰值显存、特征维度。

同一配置跨 seeds 使用均值 ± 标准差；多方法成对比较时优先使用 paired bootstrap 或 Wilcoxon signed-rank，并报告效应量。检测指标按“客户端-轮次”统计时要明确 micro/macro 口径，主文建议报告每轮 macro 均值。

## 6. 论文中必须说明的限制

- 服务器能够看到单个客户端更新；若使用完全隐藏单个更新的安全聚合，当前 AE-SVDD 不能直接部署。FedGT/ELFL/SMTFL 等安全聚合方向应作为不同威胁模型讨论；
- 单中心假设依赖正常客户端占多数。α 很小或恶意率接近/超过 50% 时，可能出现多正常簇和中心污染，应报告失败案例；
- `lie` 使用良性更新统计量，是强攻击者基线，不等同于未知攻击；
- FoolsGold、FLAME、DeepSight、FLAD、FedDMC 等论文常报告后门 ASR、干净准确率、TPR/FPR、攻击率和 non-IID 敏感性，但只有在统一实现、数据、轮数和 seeds 后才能作为数值基线；
- 论文中的“无需根数据”不等于“无需任何服务器可见信号”：本方法依赖客户端模型特征，需在威胁模型中明确。

## 7. 文献阅读结论（与实验设计的对应关系）

本仓库已保存并阅读的材料包括：Multi-Krum/NIPS-2017、Trimmed Mean 理论与综述、Dirichlet non-IID、FLDetector、FedDMC、FedSECA、FLAD、FedGT、SMTFL、以及恶意检测综述。它们反复出现的实验共同点是：

- 至少一个无攻击设置，证明防御不会靠“拒绝所有客户端”取得低 ASR；
- 数据投毒、模型投毒、后门三类攻击，且改变恶意比例；
- IID 与多个 non-IID 强度，常用 Dirichlet α 或按标签划分；
- K=10--100 的规模实验；
- Clean Accuracy/ASR 与 TPR/FPR/Precision/F1 并列报告；
- 多随机种子、收敛曲线、检测/聚合开销和失败案例；
- 对自适应/统计伪装攻击，报告检测延迟和跨轮历史行为，而非只看单轮结果。

因此本文方案把“无攻击保真性、恶意比例、non-IID、两阶段机制、后门 ASR、检测与代价”设为必做项，把未在当前代码中复现的方法明确标为扩展项。
